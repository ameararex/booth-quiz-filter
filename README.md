# Que-Fil（キューフィル）

クイズプレイヤーのためのBOOTH検索サービス。

**[Que-Filを使う](https://que-fil.ameararex.com/)**

BOOTHで「クイズ」と検索できる商品を、ショップの表示を整理しながら探せる非公式の検索補助サイトです。商品内容の確認・購入はBOOTHで行います。BOOTH・ピクシブ株式会社の公式サービスではありません。

## できること

- 商品名・ショップ名での検索。スペース区切りのAND検索に対応します。
- 新着順・スキ順・価格が高い順・価格が低い順での並べ替え。
- サムネイル付きの画像表示と一覧表示。1ページ60件、PCの画像表示は5列です。
- ショップ単位の非表示・解除。非表示設定は、このブラウザのlocalStorageに保存します。
- 共有URLやJSONファイルによる非表示リストの移行。取り込み前に内容を確認し、追加・置換を選べます。

アカウント登録は不要です。非表示は利用者個人の好みを整理するための設定であり、商品やショップの品質を評価するものではありません。

## 商品データについて

取得元は、BOOTHの[「クイズ」のキーワード検索・新着順](https://booth.pm/ja/search/%E3%82%AF%E3%82%A4%E3%82%BA?sort=new)です。タグ検索やクイズカテゴリだけに限定していません。

収集時に新着順・価格・公開スキ数などをJSONへ保存します。検索・非表示・価格やスキ数による並べ替えは、取得済みデータ全体に対してブラウザ内で行います。サイトの検索操作をきっかけにBOOTHへ商品データを取得しに行くことはありません。商品IDを公開日時の代わりには使っていません。

自動更新は、日本時間 **04:00・10:00・16:00・22:00** に起動する設定です。収集・検証・デプロイに時間がかかり、起動をスキップする場合や更新に失敗する場合もあります。実際のデータの新しさは、サイトの「最終更新」で確認してください。

取得時点と閲覧時点で、価格・販売状況・掲載内容が異なる場合があります。正確性・完全性・最新性は保証しません。最終確認と購入はBOOTHの商品ページで行ってください。サムネイルはBOOTHの画像URLを参照し、画像ファイルはこのリポジトリに保存していません。商品画像・商品名などの権利は各権利者に帰属します。

## 非表示リストの保存・共有

- **ブラウザ内の保存**：端末・ブラウザ間で自動同期されません。ブラウザのデータ消去等で失われる場合があります。
- **URL共有**：利用者が「共有リンクを作る」を押したときに、ショップID・名前のコピーをサーバーへ保存します。有効期限は7日間です。URLを知っている人は内容を取得できますが、取り込みは確認後に行います。
- **JSONファイル**：端末間の移行とバックアップに使えます。URL共有の容量を超える場合もJSONで共有できます。

BOOTH公式の非表示リストとの連携や、端末間の自動同期は行いません。通常の検索語・非表示操作で、個人設定をサーバーへ送信することはありません。

## 構成

| 役割 | 技術・処理 |
| --- | --- |
| フロントエンド | React・TypeScript・Vite・CSS |
| 画面・商品JSONの配信 | Cloudflare Workers Static Assets |
| 検索・並べ替え・非表示設定 | ブラウザ内処理・localStorage |
| URL共有 | Hono API・Cloudflare D1 |
| 商品収集 | GitHub Actions上のNode.jsスクリプト |
| 定期起動 | 専用WorkerのCloudflare Cron → GitHub Actions |

通常の画面・JSON配信ではWorkerスクリプトやD1を呼び出さず、`/api/*`だけ動的に処理します。D1は共有リストの保存用で、商品検索には使いません。

商品JSONは収集後に静的アセットとして直接デプロイします。更新のたびに生成データをGitへコミットする必要はありません。Cloudflare Workers Freeと、公開リポジトリの標準GitHub Actionsランナーを前提にしています。利用上限と運用条件は[構成](docs/architecture.md)・[共有の利用予算](docs/sharing-budget.md)を参照してください。

## ローカル開発

Node.js **24.13.0以上**を使用します。

```sh
npm ci
npm run dev
```

Viteが表示するURLで画面を開けます。この構成だけでは共有APIは動きません。

共有API・ローカルD1も使う場合：

```sh
npm run build
npm run db:local
npm run dev:worker
```

Worker版は `http://127.0.0.1:4175/` で開けます。ホスト名・ポートが異なるとlocalStorageも別になります。WindowsでWranglerのログ保存先が制限される場合は、`XDG_CONFIG_HOME`を作業ディレクトリ内の`.wrangler/config`に設定してください。

リポジトリに同梱した商品JSONは、過去に取得した開発用のスナップショットです。本番で配信中のデータ・件数・取得元とは異なる場合があります。

```sh
npm run check  # テスト・型チェック・本番ビルド
```

通常の自動テストでは、実BOOTHへの反復アクセスは行いません。

## 収集とデプロイ

本番運用はGitHub Actionsから行います。Secrets・D1・独自ドメインの準備は[初期構築手順](docs/production-trial.md)、定期起動の設定とログの見方は[自動更新の手順](docs/automation.md)を参照してください。

| ワークフロー | 用途 |
| --- | --- |
| Que-Fil initial deploy | 新しい環境での初回構築。3ページ検証後の公開に使用 |
| Que-Fil collection | `probe`で3ページ検証、`full`で最終ページまで収集。公開設定が有効な場合、全件検証・ビルド成功後にデプロイ |
| Que-Fil site deploy | 本番の商品JSON・取得日時を維持して、画面やAPIをデプロイ。BOOTHの収集はしない |
| Que-Fil scheduler deploy | 定期起動用Worker・トークン・ログ設定を反映。`enabled`で自動起動の有効・無効を選択 |

定期起動では、実行中・待機中の収集、または直近5時間以内の収集起動があるとスキップします。サイトのデプロイとスケジューラーのデプロイは別です。Cloudflare側のGitリポジトリ接続は使いません。

収集スクリプトは通信を5秒間隔で実行し、403・429・タイムアウト・パース異常等では停止します。最終ページまで取得できない場合や件数が大幅に減った場合などは、正常な公開データを置き換えないようにしています。5秒をBOOTHから安全と保証された間隔とは扱っていません。

管理者がローカルで収集する場合は `npm run collect:booth` を使用します。これは実際にBOOTHへアクセスし、ローカルの配信用JSONを更新する操作です。デプロイ自体は行いません。

認証情報はGitHub ActionsのSecretsに設定し、`.env`・`.dev.vars`・トークン・個人の非表示リストをコミットしないでください。D1のIDはリポジトリ内ではプレースホルダーです。`package.json`の`private: true`はnpmへの誤公開を防ぐ設定で、GitHubリポジトリの公開状態とは別です。
