# 技術構成

更新日: 2026-10-27。本番Actionsでの動作確認中。全件収集と定期更新は停止中。

| 用途 | 採用 |
| --- | --- |
| UI | React + TypeScript + Vite + CSS。SSRなし |
| 商品配信 | Workers Static Assetsの事前生成JSON |
| 検索・ショップ非表示 | ブラウザ内で処理 |
| 個人設定 | localStorage、JSONバックアップ |
| 商品収集 | 管理用Node.js + cheerio。UIから収集しない |
| URL共有API | Workers上のHono、/api/* のみ実行 |
| 共有保存 | D1。商品DBや自動同期とは分離 |

共有URLはリスト本体を埋め込まず、24文字のランダムIDを渡す。コピーを7日間保存し、取得側はプレビュー後に追加/置換する。認証・自動同期・アカウント登録は導入していない。共有URLを知る人は内容を取得できる。共有リンクは7日の有効期限で管理し、削除用秘密鍵や無効化操作は提供しない。

通常閲覧は静的配信で、全パスのrun_worker_firstは設定しない。D1の全件検索は行わず、共有IDの主キー検索と期限の索引を利用する。商品収集・大きなHTML解析はWorkerに持ち込まず、GitHub Actionsで実行する。ORM、KV、R2、Queuesは必要としない。

収集対象は「クイズ」タグの新着順。HTMLから価格数値を保存し、各ページの商品IDをまとめて匿名のwish_lists.jsonから公開スキ数を取得する。個人の登録状態item_idsは保存しない。人気順の収集・表示は廃止し、価格・スキ順はブラウザで計算する。同値は新着順、不明値は末尾。新着順はBOOTHの順序を保持し、IDや観測日時から公開日時を推測しない。

全件収集は最後のページまで成功してからmanifestを切り替える。3ページ検証は部分取得として明示する。固定5,000件・100ページ制限は設けず、1実行80分・800通信・配信用JSON20MiBを停止予算にする。通信間隔は5秒で、HTMLとスキ数の両方を合算する。これは安全な負荷を保証する数値ではなく、403/429・通信失敗・HTML異常時は停止し、正常なJSONを維持する。
