# 共有リンクの期限と無料枠

2026-10-27確認。共有はHono + D1でショップ設定のコピーを保存する。商品JSON、検索、通常の非表示操作は静的配信とブラウザ内の処理を維持する。

## 実装した制限

- 有効期限は作成から7日。期限を過ぎたGETは404で、レコードが残っていても内容を返さない。
- 作成はサービス全体でUTC日付ごとに500リンク（日本時間09:00に切り替え）。超過時は429。DBの原子的な更新で同時発行も制限する。
- 入力・保存するJSONは128KB（128,000バイト）以下。200ショップおよび日本語80文字の名前400ショップの作成・取得をテスト済み。名前が長い場合は同じ件数でも容量が増える。JSONファイルは画面で2MBと案内し、受付上限は余裕を持たせて2MiB（2,097,152バイト）。
- ランダムな24文字IDで取得。明示した共有操作でのみショップID・名前を送信する。検索語・旧商品設定は送らない。
- 有効期限のみで管理する。削除用秘密鍵の発行・無効化API・管理情報の保存操作は廃止。既存DBの未使用delete_hash列には空文字を保存し、既存リンクやデータを移行・削除せず運用する。
- 新規作成時に期限切れを最大20件削除。期限の索引で対象を探す。アクセスがない間も期限は延びないが、物理削除は次の作成まで遅れる。DBの空きページ再利用とファイル縮小は別なので容量も監視する。

7日間は最大8つのUTC日付にまたがるため、有効なレコードは保守的に最大4,000件、本文だけなら最大512MBとなり、全リンクが上限サイズの場合は1DBのFree上限500MBに収まらない。メタデータ・索引・DBページ等も別途必要。128KBは個別リンクの受付上限であり、毎日500件を上限サイズで保存できる保証ではない。DB容量上限に達した場合、新規共有の保存エラーを503として返し、有料プランへ自動移行しない。失効だけではアクセス回数は制限できない。

## 公式枠と利用例

Workers Freeは動的リクエスト100,000回/日、CPU 10ms/実行。[Workersの制限](https://developers.cloudflare.com/workers/platform/limits/)

D1 Freeは読み取り5,000,000行/日、書き込み100,000行/日、合計5GB。索引更新も書き込みに含まれる。[D1料金](https://developers.cloudflare.com/d1/platform/pricing/)

1つの無料DBは最大500MB。[D1制限](https://developers.cloudflare.com/d1/platform/limits/)

| 想定 | 共有API呼び出しの目安 | 結果 |
| --- | --- | --- |
| 1日1,000人、5%が1リンク作成、各リンクを2回読む | 作成50 + 取得100 = 150回/日 | リクエスト枠の0.15% |
| 1日1,000人が各10回共有リンクを読む、50件作成 | 10,050回/日 | 約10%。読み込みはIDによる1件検索、取得時の書き込みなし |
| 1日1,000人全員が1リンク作成 | 作成試行1,000回/日 | 成功500件、残り500件はアプリの上限で停止。JSON移行を案内 |
| 1日10,000人が各10回共有APIを呼ぶ | 100,000回/日 | Workers無料上限に到達。D1より先にこちらが問題になる可能性 |

通常の商品閲覧・検索回数はこの表に含めない。API以外をWorkerに通す設定へ変更すると前提が変わる。ボットや存在しないIDへのアクセス、作成拒否もWorkerの回数を使うため、期限と発行上限だけで枠消費を完全には防げない。公開時はアクセス状況を監視し、必要なら共有APIを停止する。Freeのまま運用し、有料プランへ自動移行しない。

作成1回は日次カウンタ更新、共有行挿入、期限切れ削除最大20行等を伴う。索引分も含む実際の rows_read / rows_written とCPU時間は本番D1で未測定。アカウント内の他サービスの消費も合算されるため、表は余裕の保証ではない。初期の目安は本機能の動的アクセス10,000回/日、D1書き込み10,000行/日、DB100MB以内とし、接近時に新規共有作成を停止して見直す。自動停止の監視連携は未実装。現在はCloudflareへの未公開・ローカル検証段階。
